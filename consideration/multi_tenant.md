## USER 🧑‍💻

このサービスをマルチテナント対応にしたい場合、どのような修正アプローチが考えられるか?

---

## MODEL ✨

ScholaTile をマルチテナント化（複数の組織が独立して利用できる状態）にするための主要なアプローチを、技術スタック（Prisma, Express, Preact）に基づいて整理します。

大きく分けて以下の 3 つのレイヤーでの検討が必要です。

### 1. データベースの分離レベル (Data Isolation)

Prisma と PostgreSQL を使用しているため、以下の 3 つの戦略が考えられます。

*   **共有データベース・共有スキーマ（カラムによる分離）: [推奨]**
    *   **概要:** すべてのテーブルに `tenantId` カラムを追加し、クエリ時に必ず `WHERE tenantId = ?` を付与する。
    *   **メリット:** インフラ構成が最もシンプルで低コスト。スキーママイグレーションが一括で済む。
    *   **デメリット:** クエリの実装ミスによるデータ漏洩のリスクがある（Prisma のクライアント拡張で自動化可能）。
*   **共有データベース・テナント別スキーマ:**
    *   **概要:** PostgreSQL の `Schema` 機能（命名空間）をテナントごとに作成する。
    *   **メリット:** データが物理的に分かれるため、セキュリティが高い。テナントごとのバックアップ・リストアが容易。
    *   **デメリット:** 接続先スキーマを動的に切り替えるロジックが必要。マイグレーションを全テナントに対して実行する必要がある。
*   **データベース分離 (Database-per-tenant):**
    *   **概要:** テナントごとに独立した DB インスタンス（または DB）を用意する。
    *   **メリット:** 最高の分離レベル。パフォーマンス影響を完全に遮断できる。
    *   **デメリット:** 管理コストとインフラ費用が非常に高い。

### 2. テナントの識別方法 (Tenant Identification)

ユーザーがどのテナントに属しているかを判定する方法です。

*   **サブドメイン方式 (`tenant1.scholatile.com`):**
    *   URL からテナントを即座に識別できる。Cookie の共有設定が容易。
*   **ログインベース方式:**
    *   ユーザー ID とテナントを紐付けておき、ログイン成功後の JWT（JSON Web Token）に `tenantId` を含める。既存の「ユーザーと講師の紐付け」の仕組みを拡張しやすい。
*   **リクエストヘッダー方式:**
    *   API リクエストのカスタムヘッダー（`X-Tenant-ID`）で指定する。

### 3. 具体的なコード修正ポイント

もし「共有データベース・共有スキーマ」を採用する場合、以下の修正が必要になります。

#### バックエンド (Node.js/Prisma)
1.  **Prisma Schema の更新:**
    *   `Tenant` モデルの追加（名前、サブドメイン、ステータス等）。
    *   `Resource`, `Lesson`, `Subject`, `SystemSetting` など、ほぼすべてのテーブルに `tenantId` を追加し、複合ユニーク制約（例: `name` と `tenantId`）を設定。
2.  **Prisma Client 拡張 (`$extends`):**
    *   クエリ時に自動的に `tenantId` フィルターを注入するミドルウェア的な処理を実装し、開発者が `WHERE` 句を書き忘れるのを防ぐ。
3.  **認証ミドルウェア:**
    *   JWT から `tenantId` を抽出し、`req.tenantId` として後続の処理に渡す。
4.  **監査証跡 (Audit Log):**
    *   ログ自体もテナントごとに分離して記録。

#### フロントエンド (Preact)
1.  **ログイン画面:**
    *   必要に応じて「テナント ID」の入力欄を追加、またはサブドメインから自動判別。
2.  **状態管理 (Signals):**
    *   現在ログインしているテナントの情報をグローバルで保持。
3.  **i18n / 静的アセット:**
    *   テナントごとにロゴや文言をカスタマイズしたい場合、それらを DB 管理にするか、テナント別のパスからロードする仕組みが必要。
