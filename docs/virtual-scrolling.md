# 仮想スクロール（Virtual Scrolling）設計仕様書

## 1. 概要
ScholaTile のタイムテーブル表示（特に 1ヶ月 / 3ヶ月 / 6ヶ月 / 1年 / 講座タイムライン などの長期間ビュー）において、1年分等のすべての DOM 要素を一括生成すると、大量の DOM ノードによりメモリ消費が大きくなり、レンダリングやスクロール動作が重くなる課題がある。

本ドキュメントは、表示領域（ビューポート）およびその前後のバッファ領域のみを動的に DOM レンダリングする**仮想スクロール（Virtual Horizontal Windowing）**の導入方針・技術設計をまとめたものである。

---

## 2. アーキテクチャと基本コンセプト

### 2.1 スクロール位置と可視範囲の動的計算
カレンダーコンテナの水平スクロール（`scrollLeft`）およびコンテナ幅（`clientWidth`）を監視し、現在露出している日付範囲をリアルタイムに算出する。

```
[ 全体カレンダー期間 (例: 365日) ]
 ├── 非表示領域 (描画スキップ / 空白スペーサー)
 ├── [ 左バッファ (例: 14日) ]
 ├── [ 画面表示領域 (Viewport) ]  <-- ★実際に DOM を生成・レンダリングする範囲
 ├── [ 右バッファ (例: 14日) ]
 └── 非表示領域 (描画スキップ / 空白スペーサー)
```

### 2.2 バッファ領域の確保
高速スクロール時のちらつき（白飛び）を防止するため、可視範囲の左右に適切なバッファ（例: 7〜30日分）を付与して DOM を保持する。

---

## 3. レンダリング構造の設計方針

既存の `Timetable.tsx` では `grid-template-columns` による CSS Grid レイアウトを採用している。仮想スクロール導入時には以下のアプローチをとる。

### 3.1 DOM生成の間引き（DOM Filtering / Pruning）
- **CSS Grid の保持**: `grid-template-columns` 自体は全体列数分を維持し、CSS Grid の自動配置メカニズムや列位置（`grid-column`）計算を破壊しない。
- **DOM要素のスキップ**: 表示範囲外（`colIndex < visibleStartCol || colIndex > visibleEndCol`）の日付ヘッダーセル、背景セル `<div>` の生成をスキップする。

### 3.2 カード要素（イベント・授業）の交差判定
- **ScheduleEvent / Lesson カード**:
  各カードの `startDate` 〜 `endDate` が、算出した「可視日付 ＋ バッファ範囲」と**交差（Intersection）するか**を判定し、交差するカードのみを DOM として描画する。

---

## 4. 技術的課題と対応策

### 4.1 ドラッグ＆ドロップ（D&D）・時限伸縮の維持
- **課題**: ドラッグ操作中にスクロール等で対象要素が可視範囲外に出ると、DOM がアンマウントされてドラッグ処理が中断されるリスクがある。
- **対策**: ドラッグ中 (`dragState.value !== null`) の対象授業カードについては、可視範囲外であっても強制的に DOM を保持・描画する例外フラグを適用する。

### 4.2 パフォーマンス最適化 (`@preact/signals`・rAF・Passive Listener)
- **課題**: `onScroll` イベントごとにコンポーネント全体が再レンダリングされると、逆にスクロールが遅くなる。また、JSでの同期的なスクロールハンドリングにより、ブラウザ側で `This site appears to use a scroll-linked positioning effect.` 警告やスクロールのカクつき（Jank）が発生する。
- **対策**:
  - `scrollLeft` から計算される `visibleStartIndex` と `visibleEndIndex` を `@preact/signals` で管理する。
  - スクロールイベントリスナーを `{ passive: true }` で登録し、`requestAnimationFrame` (rAF) を用いて1フレームごとにスクロール位置をバッファリング更新することで、ブラウザの非同期パンイング（Compositor Thread）をブロックしないようにする。
  - スクロール更新の閾値（しきい値）チェックを設け、バッファ範囲（14列等）の変化があった場合のみ Signal を更新する。
  - CSS に `will-change: scroll-position` や `contain` 属性を適用し、スクロール領域のコンポジットおよびレイアウト計算の分離を行う。

## 5. 導入ロードマップ

1. **Phase 1: 可視範囲計算ロジックの実装**
   - カレンダーコンテナのスクロール監視および `visibleDateRange` (`startIndex`, `endIndex`) の算出演算の実装。
2. **Phase 2: セル・ヘッダーの仮想レンダリング**
   - 日付ヘッダー、時限ヘッダー、背景セルの描画条件分岐を追加。
3. **Phase 3: イベント・授業カードのフィルタリング**
   - 期間交差判定による表示カードの絞り込み処理を追加。
4. **Phase 4: D&Dおよび各種ビュー（標準/縮小表示）での検証**
   - 既存のドラッグ＆ドロップ移動、リサイズ、Stickyヘッダー、講座タイムライン縮小表示（Reduced View）の動作検証および調整。
